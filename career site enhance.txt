Partt Group Careers build instructions

Audience a coding agent (Codex) working in the Partt website repository. Starting point the existing Careers + HR module (Next.js 16, Payload CMS 3.91.0, SQLite, CVs on local disk). See specspartt_careers_hr_reverse_spec.md and docscareers-hr-porting-guide.md for how it works today. Goal turn it into one central careers system for the whole Partt group, deployed on Vercel, that every group company website reads from.

0. Rules for the agent
Work phase by phase in the order below. Finish a phase, run npm run typecheck and npm run build, then commit before starting the next one.
Do not change unrelated website code (home, work, services, motion, nav) except where a phase says so.
Keep every payload and @payloadcms package on the same exact version (currently 3.91.0). Never mix versions.
After any change to collections, fields, relations, auth config or admin component paths, run npm run hrtypes and npm run hrimportmap.
Never commit secrets, .env.local, database files, CVs or credential files.
Never weaken an existing security rule unless a phase explicitly replaces it. Every rule in the current spec's section 8 still applies unless overridden here.
If something in this document conflicts with the actual code, or a library API differs from what's described, stop and report it. Don't guess.
Use the exact names (collections, fields, routes, env vars) given here so the pieces line up.
1. What we are building

Partt (the agency, www.parttagency.com) is the hub. It hosts

the HR dashboard (hr), used by one shared HR team for all group companies
the database and private CV storage
a public careers API that the other group websites call
Partt's own careers pages

Every other group company website (one exists now, more will follow) is a separate Vercel project. It contains no HR code. Its careers pages fetch from the Partt API, and its application form submits to the Partt API.

On every website, the careers page shows

That company's open roles at the top.
Below them, a section titled Explore other roles in our group listing open roles at all the other group companies, each with a company badge.

Adding a new company should only take (a) the admin creates a Company record in hr, and (b) the new site installs the integration kit and sets two env vars. Existing sites are not touched. The new company's roles appear in their group sections automatically.

2. Decisions already made
Topic	Decision
Hosting	All sites on Vercel. Partt project = hub.
Database	Postgres (Neon via the Vercel Marketplace) using @payloadcmsdb-postgres. SQLite files don't persist on Vercel. The module has never been deployed, so there's no production data to migrate.
CV storage	Private S3-compatible bucket (Cloudflare R2, or AWS S3) using @payloadcmsstorage-s3. Files stay private and are only served through Payload access control. Don't use Vercel Blob the Payload Vercel Blob adapter (3.x) stores public blobs, and CVs are personal data.
CV size limit	4 MB (was 5 MB). Vercel Functions reject request and response bodies over 4.5 MB, and CV downloads also pass through a function.
Rate limiting	Upstash Redis (Vercel Marketplace) with @upstashratelimit. The in-memory limiter doesn't work across serverless instances. Client IP comes from ipAddress() in @vercelfunctions.
Where a group-role click goes	To that role's page on its owning company's website (its canonical URL). Every job has exactly one canonical URL.
Job slugs	Stay globally unique across the group (simpler API, no ambiguity).
HR access	One shared HR team sees all companies. A per-company access scope is added now (default all) so a company can later get its own HR without a rebuild.
Region	Vercel functions in fra1 (Frankfurt), Neon in aws-eu-central-1, R2 with EU jurisdiction if available. Closest to Amman and keeps DB latency low.
Payload CORSCSRF	Stays limited to the Partt origin. Other company origins are allowed only on the custom public careers routes, never on apicms (that would allow cookie-authenticated requests from those sites).

Phase 4 Shared public careers library + public API
4.1 Library srclibcareerspublic.ts (server-only)

This is the single source of truth for what the public sees. Partt pages and the API routes both use it.

ts
export type PublicCompany = {
  slug string; name string; legalName string; siteUrl string; careersUrl string;
  logoUrl string  null; contactEmail string; privacyPolicyUrl string;
};
export type PublicJobSummary = {
  id number  string; slug string; title string; department string  null;
  location string; employmentType string; employmentTypeLabel string;
  workplace string; workplaceLabel string; publishedAt string  null;
  url string;                  canonical company.siteUrl + careersPath + '' + slug
  company PickPublicCompany, 'slug'  'name'  'logoUrl'  'siteUrl';
};
export type PublicJob = PublicJobSummary & {
  summary string; responsibilities string[]; requirements string[];
  company PublicCompany;
};
export type CareersListing = { company PublicCompany; jobs PublicJobSummary[]; group PublicJobSummary[] };

export async function getCareersListing(companySlug string) PromiseCareersListing  null;
export async function getPublicJob(jobSlug string) PromisePublicJob  null;
export async function getAllowedOrigins() PromiseSetstring;
export async function getActiveCompanyBySlug(slug string) PromisePublicCompany  null;

Rules

Only jobs with status = 'open' whose company is active. Never return drafts, closed jobs, inactive companies, showInGroup (internal flag), timestamps other than publishedAt, or any application data.
getCareersListing(slug)
returns null if the company doesn't exist or is inactive
jobs = that company's open jobs, sorted -publishedAt
group = open jobs of other active companies with showInGroup = true, sorted by company.sortOrder ascending, then -publishedAt
Map Payload docs to these shapes explicitly (whitelist the fields; never spread the doc). Split responsibilities  requirements into arrays with the same logic JobView uses today (trim, strip leading -•, drop empty lines). Labels come from srclibcareerslabels.ts.
Use overrideAccess true only inside this file, together with explicit where filters that enforce the rules above.
getAllowedOrigins() = every active company's siteUrl + its extraOrigins + careersOrigin + the comma-separated CAREERS_EXTRA_ORIGINS env var (for previewtesting). Querying the database on every call is fine, since it's one small query.
Replace srclibcareersqueries.ts usages with this library and delete it when nothing uses it.
